My Travel Memory

Turn trip photos into personal, shareable memory pages styled after the place you visited. This page summarises what has been built and how the system works end to end.

1. What we built

Destination themes

Five themes: MunnarGoaOotyWayanadManali each with palettes, typography, imagery, decorations and copy.

Template families

Four layouts: PosterEditorial journalCollageTimeline shared by the editor preview and the published page.

Memory editor

Step-by-step editor (details, photos, design, publish) with debounced autosave, in-browser photo compression, drag-and-drop reordering and phone/desktop preview.

Publishing & sharing

Public, unlisted or private visibility, readable slugs with a random suffix, social-preview metadata, and print/PDF output named after the trip.

Accounts

Sign up, log in, password reset, email confirmation links, settings, profile photo and account deletion, all on Supabase Auth.

Quality & safety

137 unit/component tests, Playwright end-to-end suites, pgTAP RLS tests, WCAG contrast checks on every palette, security headers and abuse limits.

2. End-to-end user flow

1. DiscoverLanding, destinations, templates and a sample memory, all without login.
2. Sign upEmail + password; confirmation link hits /auth/confirm.
3. CreatePick title, destination and template. A trip row is created.
4. EditWrite details, upload photos, choose palette/layout. Autosave runs in the background.
5. PreviewPrivate draft preview at /preview/<tripId>.
6. PublishA snapshot is written; visibility is chosen; a share link is produced.
7. VisitAnyone with access opens /memory/<slug>; print to PDF if wanted.

3. How the system works

Architecture

Browser (React client components: editor, uploads, autosave) → Next.js 16 on Vercel (App Router, server components, server actions, proxy.ts session refresh) → Supabase (Postgres with RLS, Auth, private Storage buckets).

Layers in the code

Data flow

  1. Edit & save: fields are saved via validated server actions with debounced autosave per field group; the save indicator shows state.
  2. Photos: compressed in the browser (EXIF/GPS stripped), uploaded straight to the private trip-photos/<user>/<trip>/<photo>.jpg path; the server then verifies the object's real size and type before recording it.
  3. Publish: a snapshot is stored in published_memories holding storage paths only, never URLs.
  4. View: the server checks access, then creates 1-hour signed URLs only for photos listed in that publication.

Security model

  • Every protected page and action verifies the user on the server; proxy.ts redirects are convenience only.
  • Row Level Security on every table; triggers and CHECK constraints ensure owners only touch their own trips, photos and storage paths.
  • Public memories are listable; unlisted/private ones are reachable only via the get_published_memory(slug) function (private = owner only). Unlisted pages send noindex.
  • Limits: 100 trips per account, 60 photos per trip, 10 MB per photo, JPEG/PNG/WebP only, 1 MB server-action bodies.
  • The Supabase secret key is used server-side only (signing photo URLs, account deletion).
  • Security headers: X-Frame-Options: DENY, nosniff, strict referrer and permissions policies.

Running without Supabase

If Supabase variables are missing, the site still renders; accounts, saving and uploads are off, a banner links to /setup, and in development only /editor/demo offers a sample editor.

4. Testing

  • pnpm test – Vitest unit/component tests (themes, validation, autosave, templates, server-action authorisation).
  • pnpm test:e2e – Playwright public, demo-editor and full account-flow suites.
  • supabase test db – pgTAP tests for RLS and visibility.
  • pnpm check – lint, typecheck, tests and build in one go.

6. Known limitations (Phase 1)

  • HEIC photos are not converted; users should export JPEG.
  • Upload progress shows stages, not a percentage.
  • Legal pages are drafts needing review before launch.
  • Mobile performance needs another pass (home page Lighthouse perf ~65).
  • Backups, Storage replication and a restore drill must be set up before launch.
